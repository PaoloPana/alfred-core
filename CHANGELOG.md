# Changelog

## [Unreleased] - yyyy-mm-dd

The transport is now an MQTT 5 broker (e.g. Mosquitto) instead of ZeroMQ. `AlfredModule` and `Connection` keep their API, but modules built on 0.4 or older cannot talk to modules built on this version.

### Migration from 0.4
1. Install and start an MQTT 5 broker (see `docs/broker.md` and the sample `mosquitto.conf`). The `daemon` binary does not exist anymore: remove `"daemon"` from `modules` in `config.toml`.
2. In `[alfred]` of `config.toml` replace `url`, `pub_port` and `sub_port` with `broker_url = "mqtt://127.0.0.1:1883"` (plus the optional keys below). A configuration (or environment: `ALFRED_URL`, `ALFRED_PUB_PORT`, `ALFRED_SUB_PORT`) that still has the old keys stops at start with a message explaining this.
3. Update all your modules to this version: they must all use the same transport.
4. In your modules: add `..Message::default()` to every `Message { ... }` struct literal that lists all the fields (there is a new `id` field); use the new `Config::get_module_name`/`AlfredConfig::broker_url` instead of `Config::get_alfred_pub_url`/`get_alfred_sub_url`; if you call `Message::encode`/`decode` directly, see below. Topics that relied on string-prefix matching (`listen("console")` receiving `consolex`) must be listened to explicitly: subscriptions now match whole segments (`a.b` receives `a.b` and `a.b.c`).
5. Python (or other languages) modules: see `docs/protocol.md`.

### Added
- MQTT 5 transport on [`rumqttc`](https://crates.io/crates/rumqttc) with `rustls` (`ring` provider): no OpenSSL, no libzmq, no C++/cmake needed for `cross` builds
- Persistent sessions: every module connects with a stable client id (module name, plus `instance_id` if set), `clean_start = false` and a session expiry, so a module which was offline receives the messages published meanwhile
- Presence: retained `online` on `module/<name>/status`, with an `offline` last will (also published by the new `Connection::disconnect`). Listening to these topics returns a `Text` message with the status as payload
- `Message::id`, a unique id (UUID v4) generated by `Connection::send` on every publication; `Connection::receive_all` (and so `receive`) drops the duplicate deliveries of QoS 1 using a cache of the last 1024 ids
- `Message::encode_with_id`
- Configuration keys `broker_url`, `username`, `password`, `ca_file`, `qos`, `session_expiry_secs`, `instance_id` in `[alfred]` and the environment variables `ALFRED_BROKER_URL`, `ALFRED_USERNAME`, `ALFRED_PASSWORD`, `ALFRED_CA_FILE`, `ALFRED_QOS`, `ALFRED_SESSION_EXPIRY_SECS`, `ALFRED_INSTANCE_ID`. `Debug` of the configuration hides the password
- `Config::from_parts`, `Config::get_module_name`, `Config::with_default_module_name`, `AlfredConfig::default`
- `alfred_core::topic`: the conversion between Alfred topics (dots) and MQTT topics (slashes)
- `Error::InvalidTopic`, `Error::InvalidConfig` and `Error::MqttError`
- `docs/broker.md` (setup, configuration, security), `docs/protocol.md` (exact byte layout), a sample `mosquitto.conf`, integration tests against a real broker and a CI step which starts Mosquitto

### Modified
- **Breaking:** the transport is MQTT 5: `PROTOCOL_VERSION` is now `4`, and a message is a single MQTT payload `[version][header length: u32 big endian][MessagePack header][payload]` (same header scheme, new `id` field)
- **Breaking:** `Message::encode` returns one `Bytes` instead of `[Bytes; 2]`, and `Message::decode` takes a `&Bytes` instead of a slice of frames
- **Breaking:** new public field `Message::id`
- **Breaking:** `[alfred]` configuration: `url`, `pub_port`, `sub_port` are replaced by `broker_url`; `Config::get_alfred_pub_url` and `get_alfred_sub_url` and the `AlfredConfig` fields `url`, `pub_port`, `sub_port` are removed
- **Breaking:** `Error::ZmqError` is removed (see `Error::MqttError`)
- **Breaking:** subscriptions match whole topic segments instead of any string prefix. The empty topic still receives everything
- `Connection::listen` returns when the broker has confirmed the subscription, so the messages published after it returns are received (this replaces the 1 s sleep at start-up, which is removed)
- `Connection::new` waits up to 30 s for the broker; a refused login or an untrusted certificate fails immediately
- `logs` shows the presence messages as text instead of a decode warning

### Removed
- The `daemon` binary, the `zmq2` feature and the `zeromq` and `zmq2` dependencies

### Known limitations
- Topics cannot contain `/`, `+`, `#`, empty segments or `\0`, and `listen` does not accept MQTT wildcards
- Messages are acknowledged to the broker when they are received by the library, before the module processes them

## [0.3.0] - 2026-10-01

### Added
- Added `PROTOCOL_VERSION` (`3`), sent as the first byte of every message header: `Message::decode` rejects any other version with `MessageEncodingError::ProtocolVersion`. Messages sent by older alfred-core versions are always rejected: they have no payload frame, and apart from `Photo` their first byte is not `3`
- Added `Message::text`, which returns the payload as `&str` or `Error::PayloadNotText`, and `Message::payload_description`, which returns the text or `<N bytes>` for binary payloads
- Re-exported `bytes`

### Modified
- **Breaking:** messages are now binary. Every message is sent as three ZeroMQ frames: topic, header (protocol version followed by the metadata encoded in MessagePack with named fields) and payload (raw bytes). Modules built on alfred-core 0.2.x or older cannot exchange messages with this version
- **Breaking:** replaced `Message::text: String` with `Message::payload: Bytes`, so a message can carry any binary content. `Audio` and `Photo` messages still carry a file path as text
- **Breaking:** replaced `Message::compress`/`decompress` with `Message::encode`/`decode`, and `MessageType::compress`/`decompress` with `MessageType::encode`/`decode` (`u8` instead of `char`); removed `impl Display for Message`
- **Breaking:** `Message::reply` and `Message::reply_chunk` accept any `impl Into<Bytes>` as payload
- **Breaking:** renamed `MessageCompressionError` to `MessageEncodingError` and `Error::MessageCompressionError` to `Error::MessageEncodingError`; `Error::PublishError` now contains only the topic
- **Breaking:** `MessageType` is now `#[non_exhaustive]`: a `match` on it needs a `_` arm (e.g. `MessageType::Photo | _`), so new message types can be added in minor releases without breaking modules
- Missing header fields are decoded with their default value and unknown header fields are ignored: new header fields can be added in minor releases, and the protocol version changes only for incompatible changes
- Params, response topics, sender and stream id can contain any char (including `\0`), and a message can have any number of params and response topics
- `Connection::receive` (and so `AlfredModule::receive`) now logs and discards messages that cannot be decoded instead of returning an error, so a module built on an older alfred-core cannot stop the other modules
- `logs` now shows a warning for messages that cannot be decoded instead of exiting, and shows binary payloads as `<N bytes>`
- Moved tests out of the source files: public API tests in `tests/`, tests of private functions in a `tests.rs` file next to their module

### Removed
- Removed `itertools` dependency

### Fixed
- Fixed memory leak in `Connection::send_event`, which leaked the topic string of every event sent
- Fixed `ModuleDetailsBuilder::build` setting the module name as version

## [0.2.1] - 2026-09-10

### Added
- Added `StreamText`, `StreamAudio` and `StreamPhoto` variants to `MessageType`, for messages sent as a stream of chunks
- Added `is_final`, `stream_id` and `sequence` fields to `Message` (all ignored for non-stream types): `is_final` marks the last chunk of a `Stream*` message, `stream_id` lets a receiver tell apart chunks of concurrently in-flight streams, and `sequence` is a chunk's 0-based position within its stream. The new `Message::reply_chunk` sets all three explicitly; `Message::reply` delegates to it with `is_final: true` (a plain reply is a complete, one-chunk message)
- Added `AlfredModule::send_stream(topic, message)` and `AlfredModule::send_event_stream(publisher_name, event_name, message)`, which send one stream chunk and fill in `message.stream_id` when it's empty, returning the id used so the caller can pass it into the next chunk

### Fixed
- Fixed `Message::decompress` panicking/corrupting data for message types encoded above `0x7F` (e.g. `ModuleInfo`, and now the `Stream*` types), which byte-sliced the compressed string instead of slicing by char
